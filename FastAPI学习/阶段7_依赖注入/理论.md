## 知识点 7.1：什么是依赖注入

### ① 先搞懂前置概念：什么是"依赖"？

在写代码之前，我们先想一个生活中的场景：

> 你要做一道番茄炒蛋，你需要什么？
> —— 需要鸡蛋、番茄、锅、煤气灶。

这些东西就是你做这道菜的**"依赖"**——没有它们，菜做不出来。

回到代码世界，**依赖 = 函数运行所需要的资源**。

比如你写了一个 Agent 聊天接口，它需要：
- 📦 **数据库连接**（用来存聊天记录）
- 👤 **当前用户信息**（用来知道谁在说话）
- 🔑 **API Key**（用来调用大模型）

这些东西，函数自己变不出来，必须有人"提供"给它。这些"提供"的东西，就叫**依赖**。

### ② 传统方式的问题：什么都要自己准备

如果没人帮你准备，函数就得**自己搞定一切**：

```python
import pymysql
import jwt
import yaml
import openai

# 传统方式：每个函数都要自己创建数据库连接、自己验证用户...
@app.post("/chat")
async def chat(message: str, request: Request):
    # 自己创建数据库连接
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    # 自己验证用户
    token = request.headers["Authorization"].replace("Bearer ", "")
    user = jwt.decode(token, "your-secret-key", algorithms=["HS256"])
    # 自己获取 API Key
    with open("config.yaml", "r") as f:
        config = yaml.safe_load(f)
    api_key = config["openai"]["api_key"]
    
    # 终于可以做正事了！
    client = openai.OpenAI(api_key=api_key)
    response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": message}]
    )
    reply = response.choices[0].message.content
    cursor = db.cursor()
    cursor.execute("INSERT INTO chats (user_id, message, reply) VALUES (%s, %s, %s)",
                   (user["user_id"], message, reply))
    db.commit()
    db.close()
    return {"reply": reply}

@app.get("/history")
async def history(request: Request):
    # 又要重复写一遍...
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    token = request.headers["Authorization"].replace("Bearer ", "")
    user = jwt.decode(token, "your-secret-key", algorithms=["HS256"])
    
    cursor = db.cursor()
    cursor.execute("SELECT message, reply FROM chats WHERE user_id = %s", (user["user_id"],))
    chats = [{"message": row[0], "reply": row[1]} for row in cursor.fetchall()]
    db.close()
    return chats
```

**问题一目了然：**

| 问题 | 说明 |
|------|------|
| 🔁 **代码重复** | 每个接口都要写一遍 `create_db_connection`、`verify_token`，复制粘贴满天飞 |
| 🔧 **难以修改** | 数据库地址改了？要改 10 个接口 |
| 🧪 **难以测试** | 想换个假数据库做测试？得把每个函数里的 `create_db_connection` 都改掉 |
| 🤯 **函数太胖** | 函数 80% 的代码在准备资源，真正做正事的只有 20% |

### ③ 依赖注入是什么？

**依赖注入 = 让框架自动把函数需要的资源"送进来"，函数只管拿来用。**

还是用餐厅来类比：

| | 传统方式（自己带餐具） | 依赖注入（餐厅提供） |
|---|---|---|
| 🍽️ 场景 | 你去餐厅吃饭，自己从家带餐具、带调料、带纸巾 | 你到餐厅，餐具、调料、纸巾全都准备好了 |
| 😰 问题 | 每次出门都要检查带没带筷子，忘带就吃不了 | 什么都不用带，人到就行 |
| ✨ 好处 | — | 你只需要专注一件事：**点菜、吃饭** |

对应到代码：

| | 传统方式 | 依赖注入方式 |
|---|---|---|
| 数据库连接 | 函数自己 `create_db_connection()` | 框架自动准备好，传给函数 |
| 用户认证 | 函数自己 `verify_token()` | 框架自动验证好，传给函数 |
| 函数只需要做 | 准备资源 + 做正事 | **只做正事** |

### ④ "注入"是什么意思？

**注入 = 把资源"送进"函数里。**

你可以这样理解：
- 函数说："我需要一个数据库连接"
- FastAPI 说："好的，我帮你准备好，塞到你参数里"
- 这个"塞进去"的动作，就叫**注入**

```python
# 不用自己创建，框架自动"注入"进来
@app.post("/chat")
async def chat(message: str, db=Depends(get_db), user=Depends(get_current_user)):
    # db 和 user 都是框架自动准备好"注入"进来的
    # 函数只管直接用！
    response = call_llm(message)
    db.save_chat(user, message, response)
    return {"reply": response}
```

### ⑤ 核心价值总结

| 价值 | 通俗解释 | Agent 场景举例 |
|------|----------|----------------|
| **解耦** | 函数不用关心资源怎么来的 | 聊天函数不用管数据库怎么连 |
| **复用** | 一份准备代码，到处使用 | `get_db` 写一次，100 个接口都能用 |
| **可测试** | 可以轻松替换成假的 | 测试时用假数据库，不影响真数据 |
| **可配置** | 集中管理资源的创建方式 | 改数据库地址只改一个地方 |

## 知识点 7.2：基础语法

### ① Depends() 是什么？

**`Depends()` = 告诉 FastAPI："这个参数，请帮我准备好。"**

你可以把 `Depends()` 理解成一张**"代购单"**：

> 你去餐厅，对服务员说："我要一个数据库连接"
> 服务员（FastAPI）看到你的代购单（`Depends`），去后厨（依赖函数）取来给你。

```python
import pymysql

# 依赖函数：负责"准备资源"
def get_db():
    """创建并返回一个数据库连接"""
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    return db

@app.post("/api/v1/chat")
async def chat(message: str, db=Depends(get_db)):
    # Depends(get_db) 的意思是：
    # "FastAPI，请帮我调用 get_db()，把结果塞到 db 参数里"
    # 你不用管 db 怎么来的，直接用就行
    cursor = db.cursor()
    cursor.execute("INSERT INTO chats (message) VALUES (%s)", (message,))
    db.commit()
    return {"row_id": cursor.lastrowid, "message": message}
```

**拆解一下这个过程：**

```
1. 请求到达 → FastAPI 看到 chat 函数有个参数 db=Depends(get_db)
2. FastAPI 自动调用 get_db() → 得到 pymysql 数据库连接对象
3. 把结果"注入"到 db 参数 → chat 函数拿到的 db 已经是现成的了
4. chat 函数直接 return → 完事
```

### ② yield 的作用：先给资源，用完再回收

有些资源是"借"来的，用完要"还"。比如数据库连接——用完要关闭。

**`yield` 就像"借东西"：先把东西给你，等你用完了，我再收回来。**

```python
import pymysql

def get_db():
    # 【第一步：准备资源】
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    print("数据库连接已创建")
    
    # 【第二步：把资源交给函数使用】
    yield db    # <-- 暂停在这里，让 chat 函数用 db
    # chat 函数执行完毕后，代码从这里继续往下走
    
    # 【第三步：回收资源】
    db.close()
    print("数据库连接已关闭")
```

用时间线来理解：

```
时间 →
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│  get_db()   │     │  chat()      │     │  get_db()    │
│  创建连接    │ ──→ │  使用连接     │ ──→ │  关闭连接     │
│  yield db   │     │  做正事...    │     │  yield 之后  │
└─────────────┘     └──────────────┘     └──────────────┘
     准备资源            使用资源            回收资源
```

### ③ try/finally 的作用：确保资源一定会被回收

问题来了：如果 chat 函数执行到一半**报错了**，资源还能被回收吗？

**`try/finally` 就是保证"不管出不出错，资源都会被回收"。**

```python
import pymysql

def get_db():
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    try:
        # try 里面是"把资源借出去"
        yield db
    finally:
        # finally 里面是"不管发生什么，都要把资源收回来"
        # 即使 chat 函数报错了，这里也一定会执行
        db.close()
        print("数据库连接已安全关闭")
```

**生活类比：**

> 你去图书馆借书（`yield`）：
> - 正常情况：看完还回去（`finally` 执行）
> - 突然停电了（函数报错）：图书馆关门了，但书还是要还（`finally` 依然执行）
> 
> `finally` = "无论如何都要做的事"

### ④ 完整示例：Agent 记忆存储

```python
import pymysql
from fastapi import FastAPI, Depends

app = FastAPI()

def get_agent_memory():
    """获取 Agent 的记忆存储连接（用完自动关闭）"""
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    try:
        yield db          # 把数据库连接交给接口使用
    finally:
        db.close()        # 不管出不出错，都要关闭

@app.post("/api/v1/agent/remember")
async def agent_remember(
    content: str,
    db = Depends(get_agent_memory)    # 框架自动准备好 db
):
    """让 Agent 记住一些东西"""
    cursor = db.cursor()
    cursor.execute("INSERT INTO memories (content) VALUES (%s)", (content,))
    db.commit()
    cursor.execute("SELECT COUNT(*) FROM memories")
    total = cursor.fetchone()[0]
    return {
        "status": "remembered",
        "content": content,
        "total_memories": total
    }
```

## 知识点 7.3：类作为依赖

### ① 为什么用类？

当相关的功能比较多时，用函数就不够用了。这时候用**类**把相关功能"打包"在一起，更整齐。

**生活类比：**
> - 一个函数 = 一把螺丝刀（只能拧螺丝）
> - 一个类 = 一个工具箱（里面有螺丝刀、锤子、钳子，还能记住上次用了什么）

在 Agent 场景中，一个"Agent 服务"可能需要：连接数据库、调用大模型、管理记忆——把这些打包成一个类，比写一堆散落的函数清晰得多。

```python
class AgentService:
    """Agent 服务：把相关功能打包在一起"""
    
    def __init__(self):
        self.model = "gpt-4"
        self.memory = []
    
    def call_llm(self, message: str) -> str:
        """调用大模型"""
        return f"[{self.model}] 回复: 收到消息 '{message}'"
    
    def add_memory(self, content: str):
        """添加记忆"""
        self.memory.append(content)
    
    def get_stats(self) -> dict:
        """获取统计信息"""
        return {
            "model": self.model,
            "memory_count": len(self.memory)
        }
```

### ② __call__ 方法：让类像函数一样被调用

FastAPI 的 `Depends()` 需要一个"可调用的东西"——函数天然可以调用，那类呢？

**`__call__` 方法的作用：让类的实例也能像函数一样被"调用"。**

```python
class AgentService:
    def __init__(self):
        self.model = "gpt-4"
    
    def __call__(self):
        # 当 FastAPI 调用 Depends(agent_service) 时，
        # 实际上就是执行这个 __call__ 方法
        return {
            "model": self.model,
            "status": "ready"
        }

# 创建一个实例
agent_service = AgentService()

# 下面两种写法效果一样：
result = agent_service()       # 像函数一样调用
result = agent_service.__call__()   # 显式调用 __call__
```

**在 FastAPI 中使用：**

```python
from fastapi import FastAPI, Depends

app = FastAPI()

class AgentService:
    def __init__(self):
        self.model = "gpt-4"
    
    def __call__(self):
        """FastAPI 会自动调用这个方法"""
        return {"model": self.model, "status": "ready"}

agent_service = AgentService()

@app.post("/api/v1/chat")
async def chat(message: str, agent = Depends(agent_service)):
    # agent 就是 __call__ 的返回值
    return {"agent": agent, "message": message}
```

## 知识点 7.4：依赖注入的高级用法

### ① 依赖链：像套娃一样一层套一层

**依赖链 = A 依赖 B，B 依赖 C，FastAPI 会自动把整条链都准备好。**

**生活类比：**
> 你要做一道菜（A），需要酱料（B），酱料需要原材料（C）。
> 你不用管 C 怎么变成 B、B 怎么变成 A，厨房（FastAPI）全帮你搞定。

```python
import pymysql
import openai
from fastapi import FastAPI, Depends

app = FastAPI()

# 第 1 层：最基础的配置
def get_llm_config():
    """获取大模型配置"""
    return {"model": "gpt-4", "api_key": "sk-xxx"}

# 第 2 层：依赖第 1 层
def get_llm_client(config = Depends(get_llm_config)):
    """创建大模型客户端（需要配置）"""
    return openai.OpenAI(api_key=config["api_key"])

# 第 3 层：依赖第 2 层
def get_agent(llm_client = Depends(get_llm_client)):
    """创建 Agent（需要大模型客户端）"""
    return llm_client

@app.post("/api/v1/agent/run")
async def run_agent(task: str, client = Depends(get_agent)):
    # FastAPI 自动完成的链路：
    # 1. 先调用 get_llm_config() → 得到配置
    # 2. 再把配置传给 get_llm_client() → 得到 OpenAI 客户端
    # 3. 再把客户端传给 get_agent() → 返回客户端
    # 4. 最后把客户端注入到这个函数里
    response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": task}]
    )
    return {"reply": response.choices[0].message.content}
```

**依赖链的流程图：**

```
get_llm_config()          ← 第 1 层：准备配置
    ↓
get_llm_client(config)    ← 第 2 层：用配置创建客户端
    ↓
get_agent(llm_client)     ← 第 3 层：用客户端创建 Agent
    ↓
run_agent(agent)          ← 最终：Agent 注入到接口函数
```

### ② 全局依赖 vs 路由级别依赖

**区别一句话：**
- **全局依赖** = 大楼的门禁，所有人都要刷卡才能进
- **路由级别依赖** = 某个房间的门禁，只有进这个房间才需要刷卡

#### 全局依赖：所有接口都要检查

```python
from fastapi import FastAPI, Depends, HTTPException

app = FastAPI()

def verify_api_key(api_key: str = Header(...)):
    """验证 API Key（所有接口都要检查）"""
    if api_key != "valid-key-123":
        raise HTTPException(status_code=401, detail="无效的 API Key")
    return {"key": api_key}

# 全局依赖：所有接口都会先执行 verify_api_key
app = FastAPI(dependencies=[Depends(verify_api_key)])

@app.post("/api/v1/chat")
async def chat(message: str):
    # 不用写 verify_api_key，全局已经检查过了
    return {"reply": f"收到: {message}"}

@app.get("/api/v1/history")
async def history():
    # 这里也自动检查了 API Key
    return {"history": []}
```

**适用场景：** 所有接口都需要做的事，比如 API Key 验证、请求日志、限流。

#### 路由级别依赖：只有特定接口组检查

```python
from fastapi import APIRouter, Depends, HTTPException

router = APIRouter()

def verify_admin(token: str = Header(...)):
    """验证管理员身份（只有管理接口需要）"""
    if token != "admin-token":
        raise HTTPException(status_code=403, detail="需要管理员权限")
    return {"role": "admin"}

# 路由级别依赖：只有这个 router 下的接口才检查管理员身份
admin_router = APIRouter(dependencies=[Depends(verify_admin)])

@admin_router.delete("/api/v1/agent/{agent_id}")
async def delete_agent(agent_id: str):
    # 只有管理员才能访问
    return {"deleted": agent_id}

@admin_router.post("/api/v1/agent/config")
async def update_config(config: dict):
    # 也只有管理员才能访问
    return {"updated": True}
```

**对比总结：**

| | 全局依赖 | 路由级别依赖 |
|---|---|---|
| 🏢 类比 | 大楼门禁（所有人都要刷卡） | 房间门禁（只有进特定房间才刷卡） |
| 📍 作用范围 | 整个应用的所有接口 | 某个路由组下的接口 |
| 🔧 典型用途 | API Key 验证、日志、限流 | 管理员权限、特定业务检查 |
| 💡 何时使用 | 所有接口都要做的事 | 只有部分接口需要做的事 |

### ③ 依赖覆盖（测试时替换依赖）

依赖注入还有一个强大功能：**测试时可以替换依赖**。

```python
import pymysql

# 正式环境：连接真实数据库
def get_db():
    db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
    try:
        yield db
    finally:
        db.close()

# 测试环境：用假数据模拟（不连真实数据库，测试完直接丢弃）
def get_test_db():
    fake_db = {"users": [], "logs": []}  # 用字典模拟数据库
    yield fake_db

# 测试时覆盖依赖
# app.dependency_overrides[get_db] = get_test_db
# 这样所有用 get_db 的地方都会自动换成 get_test_db
# 真实库 → 假数据，测试不污染生产环境，也不用清理数据库
```

## 知识点 7.5：Agent 场景应用

### ① 认证依赖：验证 Agent 调用者身份

```python
import pymysql
import jwt
from fastapi import FastAPI, Depends, HTTPException, Header

app = FastAPI()

SECRET_KEY = "your-secret-key"

async def get_current_user(x_api_key: str = Header(...)):
    """验证调用者身份，返回用户信息"""
    try:
        payload = jwt.decode(x_api_key, SECRET_KEY, algorithms=["HS256"])
        user_id = payload["user_id"]
        db = pymysql.connect(host="localhost", user="root", password="password", database="agent_db")
        cursor = db.cursor()
        cursor.execute("SELECT name, role FROM users WHERE id = %s", (user_id,))
        row = cursor.fetchone()
        db.close()
        if not row:
            raise HTTPException(status_code=401, detail="用户不存在")
        return {"name": row[0], "role": row[1]}
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail="无效的 Token")

@app.post("/api/v1/agent/chat")
async def agent_chat(
    message: str,
    user = Depends(get_current_user)    # 自动验证身份
):
    """Agent 聊天接口，只有认证用户才能使用"""
    return {
        "user": user["name"],
        "role": user["role"],
        "reply": f"你好 {user['name']}，收到你的消息: {message}"
    }
```

### ③ 多依赖组合：完整的 Agent 调用链

```python
from fastapi import FastAPI, Depends, Header, HTTPException

app = FastAPI()

def get_current_user(x_api_key: str = Header(...)):
    """依赖 1：验证用户"""
    users = {"key-alice": {"name": "Alice", "quota": 100}}
    user = users.get(x_api_key)
    if not user:
        raise HTTPException(status_code=401, detail="未授权")
    return user

def get_llm_config():
    """依赖 2：获取大模型配置"""
    return {"model": "gpt-4", "max_tokens": 2000}

def get_agent(user = Depends(get_current_user), config = Depends(get_llm_config)):
    """依赖 3：组合用户和配置，创建 Agent"""
    if user["quota"] <= 0:
        raise HTTPException(status_code=429, detail="配额已用完")
    return {
        "user": user["name"],
        "model": config["model"],
        "status": "ready"
    }

@app.post("/api/v1/agent/run")
async def run_agent(task: str, agent = Depends(get_agent)):
    """运行 Agent（自动完成认证 + 配置 + 配额检查）"""
    return {
        "agent": agent,
        "task": task,
        "result": f"Agent {agent['user']} 正在处理: {task}"
    }
```

## 知识点 7.6：Harness 架构视角分析

### ① 依赖注入在 Harness 中的作用

| 作用 | 通俗解释 | Agent 场景举例 |
|------|----------|----------------|
| **边界控制** | 通过依赖注入统一控制资源访问 | 所有数据库操作都经过 `get_db`，方便统一加日志 |
| **错误恢复** | 依赖的异常可以统一处理 | 数据库连接失败时，`finally` 确保资源被清理 |
| **上下文管理** | 依赖注入是上下文传递的核心机制 | 用户信息、对话上下文通过依赖链自动传递 |
| **反馈回路** | 依赖可以注入监控和日志组件 | 每个请求自动记录耗时、token 消耗 |

### ② 补偿性代码 vs 系统性工程

| 方式 | 判断 | 说明 |
|------|------|------|
| 使用 `Depends` | ✅ 系统性工程 | 框架提供的标准化依赖管理 |
| 全局依赖 | ✅ 系统性工程 | 统一的横切关注点处理 |
| 依赖链 | ✅ 系统性工程 | 自动处理复杂的依赖关系 |
| 手动创建依赖 | ❌ 补偿性代码 | 代码重复，耦合度高 |
| 每个接口手写认证 | ❌ 补偿性代码 | 改一个逻辑要改 N 个地方 |

### ③ Harness 设计原则

```
┌─────────────────────────────────────────────┐
│              Harness 架构                    │
│                                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 认证依赖  │  │ 配置依赖  │  │ 日志依赖  │  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  │
│       │             │             │         │
│       └─────────────┼─────────────┘         │
│                     ↓                       │
│            ┌────────────────┐               │
│            │  Agent 核心逻辑 │               │
│            │  (只做正事)     │               │
│            └────────────────┘               │
│                     ↓                       │
│            ┌────────────────┐               │
│            │  资源自动回收    │               │
│            │  (finally保障)  │               │
│            └────────────────┘               │
└─────────────────────────────────────────────┘
```

## 📌 章节总结

### 知识点在 Agent 项目中的落地位置

| 场景 | 依赖注入的作用 | 举例 |
|------|--------------|------|
| **认证授权** | 验证调用者身份 | `Depends(get_current_user)` |

| **权限控制** | 区分管理员和普通用户 | 路由级别依赖 |

| 依赖链 | ✅ 必须掌握 | 处理复杂依赖关系 |
