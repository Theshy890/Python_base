## 知识点 1.1：什么是FastAPI

### ① 一句话通俗定义

**FastAPI = Python界的"闪电侠"API框架，专门为快速构建高性能Web服务而生。**

### ② 生活化类比

想象你是一家AI公司的老板，需要搭建一个"大模型服务窗口"：

| 传统方式（Flask/Django） | FastAPI方式 |
|--------------------------|-------------|
| 像去银行柜台办事，排队慢，流程繁琐 | 像用自助取款机，即插即用，秒级响应 |
| 需要手写大量验证代码 | 自动生成文档和校验 |
| 同步处理，一次只能服务一个客户 | 异步处理，同时服务多个客户 |

### ③ 核心优势（为什么选FastAPI搭建Agent后端）

| 优势 | 对Agent开发的意义 |
|------|-------------------|
| **极速性能** | 高并发处理用户请求，支持大量Agent同时运行 |
| **自动文档** | 生成交互式API文档，方便调试和对接前端 |
| **类型注解驱动** | 强制类型检查，减少运行时错误 |
| **异步支持** | 天然支持异步编程，适合调用外部API（LLM接口） |
| **Pydantic集成** | 强大的数据校验能力，确保输入输出安全 |
| **轻量级** | 不臃肿，专注API服务，适合快速迭代 |

## 知识点 1.3：写代码前必须懂的前置知识

> 💡 **重要提醒**：在动手写FastAPI代码之前，你必须先理解这些基础概念。别担心，我们用生活中的例子来解释，保证你能听懂。

### ① 什么是HTTP请求/响应？——餐厅点单的比喻

想象你去餐厅吃饭，整个过程就是HTTP请求/响应的完美类比：

| 餐厅场景 | 网络场景 | 说明 |
|---------|---------|------|
| **顾客点单** | **HTTP请求** | 你（客户端）告诉服务员（网络）你要什么 |
| **服务员记录** | **请求发送** | 把你的需求传给厨房 |
| **厨房做菜** | **服务器处理** | 服务器收到请求，开始干活 |
| **端菜上桌** | **HTTP响应** | 把结果返回给你 |

**完整的HTTP交互流程：**

```
你（浏览器/APP）  →  发送请求  →  服务器（FastAPI）
                    ←  返回响应  ←  
```

**举个Agent的例子：**
- 你打开一个AI对话网页，输入"今天天气怎么样？"
- 浏览器发送**请求**给FastAPI服务器："帮我问问AI这个问题"
- FastAPI调用大模型处理，然后返回**响应**："AI说今天晴天，25度"

### ② 什么是GET请求 vs POST请求？

这两种是最常见的HTTP请求方法，区别很简单：

| 请求方法 | 生活类比 | 用途 | 例子 |
|---------|---------|------|------|
| **GET** | 去图书馆**借书看** | 获取数据，不修改任何东西 | 查看Agent状态、获取对话历史 |
| **POST** | 去快递点**寄包裹** | 提交数据，让服务器处理 | 发送消息给AI、创建新任务 |

**更通俗的解释：**

- **GET = "我要看"**：只是看看，不动东西
  - 比如：打开网页看新闻、查询天气、获取Agent列表
  - 特点：数据放在URL里，有长度限制，可以被收藏

- **POST = "我要交"**：提交东西给服务器处理
  - 比如：登录账号、发送消息给AI、上传文件
  - 特点：数据放在请求体里，没有长度限制，更安全

**Agent场景举例：**

```
GET  /api/agents          → 获取所有Agent的列表（只是看）
POST /api/agents/create   → 创建一个新的Agent（提交数据）
GET  /api/chat/history    → 获取对话历史（只是看）
POST /api/chat/send       → 发送一条消息给AI（提交数据）
```

### ③ 什么是URL路径？——就像门牌号

URL路径就是服务器上每个接口的"地址"，就像每条街都有门牌号一样：

| URL路径 | 类比 | 作用 |
|---------|------|------|
| `/` | 小区大门 | 首页，进入服务的主入口 |
| `/api/agents` | 1号楼 | Agent列表接口 |
| `/api/chat` | 2号楼 | 对话接口 |
| `/api/tools` | 3号楼 | 工具调用接口 |

**完整URL的组成：**

```
http://localhost:8000/api/chat
  │         │         │
  │         │         └── 路径（具体哪个接口）
  │         └── 端口号（哪个门）
  └── 协议+主机（哪栋楼）
```

**记住这个规则：**
- 每个路径对应一个功能
- 路径要见名知意：`/api/chat`一看就知道是对话相关的
- 路径区分大小写：`/Chat`和`/chat`是两个不同的路径

### ④ 什么是装饰器@？——给函数"贴标签"

装饰器是Python的一个语法，用`@`符号表示。在FastAPI里，它的作用是：**告诉FastAPI"这个函数负责处理哪个URL的请求"**。

**生活类比：**

想象你是餐厅老板，要给每个服务员分配任务：

```python
# 不用装饰器（传统方式）：你要手动记录谁负责什么
服务员A负责 = "前台接待"
服务员B负责 = "点单服务"

# 用装饰器（FastAPI方式）：直接给服务员贴标签
@前台接待
def 服务员A():
    print("您好，欢迎光临！")

@点单服务
def 服务员B():
    print("您想点什么？")
```

**FastAPI中的装饰器：**

```python
@app.get("/")          # 贴标签：这个函数处理"GET请求"，路径是"/"
def root():
    return {"message": "欢迎"}

@app.post("/api/chat") # 贴标签：这个函数处理"POST请求"，路径是"/api/chat"
def chat():
    return {"response": "AI回复"}
```

**装饰器的三个要素：**
1. `@app`：告诉FastAPI框架来处理
2. `.get` 或 `.post`：处理哪种请求方法
3. `("/路径")`：处理哪个URL路径

**一句话总结：** 装饰器就是给函数贴个标签，告诉FastAPI"当有人访问这个URL时，就执行这个函数"。

### ⑤ 什么是JSON？——简单的数据格式

JSON是一种数据格式，用来在网络上传输数据。它长这样：

```json
{
    "name": "小助手",
    "age": 25,
    "is_active": true,
    "skills": ["对话", "翻译", "总结"]
}
```

**JSON的三大特点：**

| 特点 | 说明 | 例子 |
|------|------|------|
| **键值对** | 数据都是"名字: 值"的形式 | `"name": "小助手"` |
| **用大括号** | 整体用`{}`包起来 | `{"key": "value"}` |
| **支持类型** | 字符串、数字、布尔值、数组 | 字符串要加引号，数字不用 |

**为什么FastAPI用JSON？**
- 人类看得懂（不像二进制数据）
- 所有编程语言都支持
- 前后端沟通的标准格式

**Agent场景中的JSON：**

```json
// 请求：用户发给AI的消息
{
    "message": "帮我写一首诗",
    "model": "gpt-4"
}

// 响应：AI返回的结果
{
    "response": "春风拂面花满枝...",
    "status": "success",
    "tokens_used": 150
}
```

**Python字典 vs JSON：**

```python
# Python字典（代码里用）
user = {"name": "张三", "age": 25}

# JSON（网络传输用）
{"name": "张三", "age": 25}
```

几乎一样！FastAPI会自动帮你把Python字典转成JSON返回给客户端。

### ⑥ 前置知识小结

| 概念 | 一句话解释 | Agent场景举例 |
|------|-----------|---------------|
| HTTP请求/响应 | 客户端和服务器之间的"对话" | 用户发消息→AI回复 |
| GET请求 | 获取数据，不修改 | 查看Agent列表 |
| POST请求 | 提交数据，让服务器处理 | 发送消息给AI |
| URL路径 | 接口的"地址" | `/api/chat`是对话接口 |
| 装饰器@ | 给函数"贴标签"，绑定URL | `@app.post("/chat")` |
| JSON | 数据格式，键值对 | `{"message": "你好"}` |

## 知识点 1.4：第一个Agent服务

> 💡 现在你已经理解了前置知识，让我们来看第一个FastAPI代码！

### ① 最小Demo：大模型API封装

```python
from fastapi import FastAPI

app = FastAPI(title="Agent后端服务", version="1.0")

@app.get("/")
def root():
    return {"message": "Agent服务已启动"}

@app.post("/api/v1/chat")
def chat(message: str):
    """
    模拟大模型对话接口
    """
    return {
        "response": f"AI收到消息：{message}",
        "status": "success"
    }

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### ② 运行方式

```bash
# 方式一：直接运行
python main.py

# 方式二：uvicorn命令
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

|------|------|
| http://localhost:8000/docs | Swagger UI（交互式文档） |

## 知识点 1.5：代码逐行解析

> 💡 这一节我们先讲概念，再看代码，确保你能真正理解每一行的含义。

### ① 概念先行：FastAPI代码的"三板斧"

写FastAPI代码，永远离不开这三步：

| 步骤 | 做什么 | 类比 |
|------|--------|------|
| **第一步：创建应用** | 创建一个FastAPI实例 | 开一家餐厅，先要有个店面 |
| **第二步：定义路由** | 用装饰器绑定URL和函数 | 给服务员分配任务：谁负责哪桌 |
| **第三步：启动服务** | 运行应用，监听请求 | 开门营业，等待顾客上门 |

### ② 逐行解释（概念+代码对照）

```python
# ==================== 第一步：创建应用 ====================
from fastapi import FastAPI
# 【概念】导入FastAPI类，这是创建"餐厅"的"建筑材料"
# 【代码】从fastapi包中导入FastAPI类

app = FastAPI(title="Agent后端服务", version="1.0")
# 【概念】创建一个FastAPI应用实例，相当于"开了一家餐厅"
#        title是餐厅名字，version是版本号
# 【代码】app就是整个服务的"总控制台"，后面所有路由都要挂在它下面

# ==================== 第二步：定义路由 ====================
@app.get("/")
# 【概念】这是一个装饰器，给下面的函数"贴标签"
#        .get表示处理GET请求（只是看，不修改）
#        "/"表示根路径，就是访问首页
# 【代码】当用户访问 http://localhost:8000/ 时，执行下面的函数
def root():
    # 【概念】这是一个视图函数，负责处理请求并返回响应
    # 【代码】函数名root可以随便起，但要有意义
    return {"message": "Agent服务已启动"}
    # 【概念】返回一个字典，FastAPI会自动转成JSON格式
    # 【代码】客户端会收到 {"message": "Agent服务已启动"}

@app.post("/api/v1/chat")
# 【概念】又一个装饰器，但这次是POST请求（提交数据）
#        "/api/v1/chat"是路径，v1表示版本1
# 【代码】当用户POST请求 http://localhost:8000/api/v1/chat 时，执行下面的函数
def chat():
    """
    模拟大模型对话接口
    """
    return {
        "response": "AI已启动，等待对话",
        "status": "success"
    }
    # 【概念】返回一个包含两个键值对的字典
    # 【代码】FastAPI会自动转成JSON返回给客户端

# ==================== 第三步：启动服务 ====================
if __name__ == "__main__":
    # 【概念】这是Python的标准写法，表示"只有直接运行这个文件时才执行"
    #        如果被其他文件导入，这部分不会执行
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
    # 【概念】uvicorn是ASGI服务器，负责"开门营业"
    #        host="0.0.0.0"表示监听所有网络接口（允许外部访问）
    #        port=8000表示监听8000端口
    # 【代码】启动后，服务会在 http://localhost:8000 运行
```

### ③ 关键概念总结

| 概念 | 通俗解释 | 在代码中的体现 |
|------|---------|---------------|
| **app** | FastAPI应用实例，相当于"服务总控制台" | `app = FastAPI(...)` |
| **路由** | URL路径和处理函数的绑定关系 | `@app.get("/")`、`@app.post("/api/v1/chat")` |
| **装饰器** | 给函数"贴标签"，告诉FastAPI谁处理哪个URL | `@app.get()`、`@app.post()` |
| **视图函数** | 处理请求的函数，返回值自动转为JSON | `def root():`、`def chat():` |
| **类型注解** | 指定参数类型，FastAPI自动校验 | `message: str` |

## 知识点 1.6：Harness架构视角分析

### ① 这个功能如何用于搭建Agent的Harness？

- **边界控制**：通过路由定义API边界，限制外部访问范围
- **错误恢复**：后续章节学习的异常处理机制可以在这里集中处理
- **上下文管理**：应用实例`app`是全局状态，可以存储配置、连接池等
- **反馈回路**：自动文档方便调试和监控，形成开发-测试-迭代闭环

### ② 补偿性代码 vs 系统性工程

| 方式 | 判断 | 说明 |
|------|------|------|
| 直接用`app = FastAPI()` | ✅ 系统性工程 | FastAPI是成熟框架，提供标准化架构 |
| 手动实现路由匹配 | ❌ 补偿性代码 | 重复造轮子，容易出错 |
| 使用自动文档 | ✅ 系统性工程 | 减少文档维护成本，长期保值 |
