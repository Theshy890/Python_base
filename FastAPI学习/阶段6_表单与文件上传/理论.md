## 知识点 6.1：表单数据

### ① 先搞懂"什么是表单"

你在网上肯定填过东西——比如登录时输入用户名和密码，注册时填写手机号、邮箱、地址……这些"填写区域"就是**表单（Form）**。

表单的本质就是：**一堆"名字-值"的配对**。比如：
- 用户名 = "张三"
- 密码 = "123456"

你一点"提交"按钮，这些数据就被发送到服务器了。

### ② Form 和 Body 有什么区别？

在前面的阶段中，我们用 `Body(...)` 或 Pydantic 模型来接收数据，那种方式叫 **JSON 提交**。现在学的 `Form(...)` 叫 **表单提交**。它们都是"客户端把数据发给服务器"的方式，但格式完全不同：

| | Form（表单提交） | Body（JSON 提交） |
|---|---|---|
| **类比** | 填纸质表格，一格一格填 | 发一份电子文档（JSON格式） |
| **数据格式** | `username=张三&password=123` | `{"username": "张三", "password": "123"}` |
| **Content-Type** | `application/x-www-form-urlencoded` 或 `multipart/form-data` | `application/json` |
| **典型场景** | 网页上的登录框、注册页 | API接口、前后端分离项目 |

**一句话总结**：Form 是"填表格"，Body 是"发文档"。服务器端需要用不同的方式去解析它们。

### ③ 为什么需要安装 python-multipart？

FastAPI 默认能处理 JSON 数据（Body），但**不能直接处理表单数据**。表单数据需要额外的"翻译工具"来解析，这个工具就是 `python-multipart`。

类比：你的服务器是一个只懂英语的人，JSON 他天生就懂，但表单数据是"法语"，需要请一个翻译（python-multipart）才能听懂。

```bash
pip install python-multipart
```

> 不装这个包，用 `Form(...)` 会直接报错。

### ④ 基本用法：用 Form 接收表单数据

```python
from fastapi import FastAPI, Form

app = FastAPI()

# 模拟Agent的登录接口：Agent用账号密码登录管理后台
@app.post("/api/v1/login")
async def login(
    username: str = Form(...),   # Form(...) 表示这个字段是表单字段，必填
    password: str = Form(...)    # 和 Body(...) 用法类似，但数据来源不同
):
    return {"username": username}
```

**代码解读**：
- `Form(...)` 中的 `...` 表示"必填"，和之前学的 `Body(...)` 一个意思
- 客户端发送请求时，必须用表单格式（而不是JSON格式）提交数据
- 如果你用 Postman 测试，记得选 `x-www-form-urlencoded` 格式

## 知识点 6.2：文件上传

### ① 先搞懂"什么是文件上传"

想象你在微信里给朋友发一张照片——你把手机里的照片"发送"出去，照片就从你的手机"跑"到了服务器上，朋友就能看到了。这个过程就是**文件上传**：把本地文件发送到服务器。

在 Agent/LLM 场景中，文件上传的典型用途：
- 用户上传 PDF 文档给 Agent 做知识库
- 上传 CSV 数据文件让 Agent 分析
- 上传配置文件给 Agent 使用

### ② UploadFile 是什么？

当客户端上传文件时，FastAPI 不会直接把整个文件塞进内存（那样太浪费资源），而是给你一个 **UploadFile 对象**——你可以把它理解为"文件的快递包裹"。

这个"包裹"里包含：

| 属性 | 说明 | 类比 |
|------|------|------|
| `filename` | 文件名 | 快递单上的"物品名称" |
| `content_type` | 文件类型（MIME类型） | 快递单上的"物品类别"（文件/液体/易碎品） |
| `file` | 实际的文件对象 | 快递包裹里的实际物品 |

你可以从这个"包裹"里读取文件内容，但需要用到 `await`（下面解释）。

### ③ File(...) 是什么意思？

`File(...)` 是一个**标记**，告诉 FastAPI："这个参数不是普通的表单字段，而是一个文件"。

- `File(...)` 中的 `...` 同样表示"必填"——必须上传文件
- 如果不写 `File(...)`，FastAPI 不知道这个参数要从文件中获取

类比：你去快递站取件，`File(...)` 就是你的取件码——告诉工作人员"我要取的是包裹，不是普通信件"。

### ④ 单文件上传

```python
from fastapi import FastAPI, File, UploadFile

app = FastAPI()

# 模拟Agent知识库文档上传
@app.post("/api/v1/upload")
async def upload_file(file: UploadFile = File(...)):
    content = await file.read()   # 读取文件内容
    return {"filename": file.filename, "size": len(content)}
```

**为什么需要 `await`？**

`file.read()` 前面有个 `await`，这是因为读取文件是一个**耗时操作**（文件可能很大，读起来要花时间）。

类比：你去图书馆复印一本500页的书。复印机在"嗡嗡嗡"地复印，你不可能站在旁边一动不动地干等——你可以先去喝杯水、回个消息，等复印机"叮"一声好了，你再过去拿。

`await` 就是这个意思："我知道这个操作要花时间，我先让出控制权去做别的事，等它完成了我再继续往下走。"这就是**异步编程**的核心思想。

### ⑤ 多文件上传

有时候需要一次上传多个文件（比如同时上传多个知识库文档），只需要把类型改成 `List[UploadFile]`：

```python
from fastapi import FastAPI, File, UploadFile
from typing import List

app = FastAPI()

# 模拟Agent批量上传知识库文档
@app.post("/api/v1/upload/multiple")
async def upload_multiple_files(files: List[UploadFile] = File(...)):
    return [
        {"filename": f.filename, "size": len(await f.read())}
        for f in files
    ]
```

**和单文件的区别**：参数类型从 `UploadFile` 变成了 `List[UploadFile]`，其他逻辑基本一样。

## 知识点 6.3：表单与文件混合

实际场景中，上传文件时往往还要附带一些文字信息。比如上传知识库文档时，除了文件本身，还要填写文档标题和描述。

这时候就需要**表单字段（Form）和文件（File）混用**：

```python
from fastapi import FastAPI, Form, File, UploadFile

app = FastAPI()

# 模拟Agent知识库：上传文档时同时填写元信息
@app.post("/api/v1/documents")
async def create_document(
    title: str = Form(...),              # 表单字段：文档标题（必填）
    description: str = Form(""),         # 表单字段：文档描述（选填，默认为空）
    file: UploadFile = File(...)         # 文件字段：上传的文件（必填）
):
    content = await file.read()
    return {
        "title": title,
        "description": description,
        "filename": file.filename,
        "content_size": len(content)
    }
```

**要点**：
- `Form(...)` 和 `File(...)` 可以写在同一个接口里
- 这种混合方式要求表单的 `Content-Type` 必须是 `multipart/form-data`（不能是普通的 `urlencoded`）
- 文字信息用 `Form(...)`，文件用 `File(...)`，各司其职

## 知识点 6.4：文件处理最佳实践

### ① 为什么要限制文件大小？

想象你的服务器是一间仓库。如果有人故意上传一个 100GB 的文件，你的仓库瞬间就被塞满了，其他人的东西就放不进来了，整个服务器可能就崩溃了。

这就是**拒绝服务攻击（DoS）**的一种简单形式——用大文件把你的服务器"撑爆"。

所以必须限制文件大小，就像仓库要规定"每件货物最大不超过50公斤"一样。

```python
from fastapi import FastAPI, File, UploadFile, HTTPException

app = FastAPI()

# 限制文件大小：最大10MB
@app.post("/api/v1/upload")
async def upload_file(file: UploadFile = File(..., description="最大10MB")):
    content = await file.read()
    if len(content) > 10 * 1024 * 1024:   # 10MB = 10 * 1024 * 1024 字节
        raise HTTPException(status_code=413, detail="文件过大")
    return {"filename": file.filename}
```

> `status_code=413` 是 HTTP 标准中"请求实体过大"的状态码，专门用于这种情况。

### ② 为什么要限制文件类型？

如果有人上传的不是文档，而是一个恶意脚本文件（比如 `.exe`、`.sh`），你的服务器不小心执行了它，那就相当于"引狼入室"。

即使不执行，某些文件类型可能包含恶意代码，或者根本不是合法的业务文件。

类比：小区门卫不能什么快递都往里放——万一有人寄了个危险物品呢？门卫要检查"这个包裹是食物/衣服（允许的），还是炸弹（禁止的）"。

```python
from fastapi import FastAPI, File, UploadFile, HTTPException

app = FastAPI()

# 只允许这些文件类型
ALLOWED_TYPES = ["text/plain", "application/pdf", "application/json"]

@app.post("/api/v1/upload")
async def upload_file(file: UploadFile = File(...)):
    if file.content_type not in ALLOWED_TYPES:
        raise HTTPException(status_code=400, detail="不支持的文件类型")
    return {"filename": file.filename}
```

> 在 Agent 场景中，通常只允许 `.txt`、`.pdf`、`.json`、`.csv` 等文档类型，因为 Agent 的知识库就是由这些格式的文档组成的。

## 知识点 6.5：Harness架构视角分析

### ① 文件上传在Harness中的作用

- **边界控制**：限制文件大小和类型，防止恶意上传。就像小区的门卫系统，不是所有东西都能进来
- **错误恢复**：统一的文件校验和错误提示。文件不合规时，给出清晰的错误信息，而不是让系统崩溃后才报错
- **上下文管理**：文件处理流程中的状态追踪。文件上传后去了哪里、被哪个 Agent 使用了，都需要追踪

### ② 补偿性代码 vs 系统性工程

| 方式 | 判断 | 说明 |
|------|------|------|
| 使用 UploadFile | ✅ 系统性工程 | 框架提供的标准文件处理机制，稳定可靠 |
| 文件大小/类型校验 | ✅ 系统性工程 | 前置校验，在文件进入系统之前就拦截问题 |
| 手动解析 multipart | ❌ 补偿性代码 | 自己写解析逻辑，复杂且容易出错，完全没必要 |

## 📌 章节总结

### 知识点在Agent项目中的落地位置

- **文档上传**：用户上传知识库文档（PDF、TXT、CSV），Agent 读取后用于回答问题
- **配置上传**：用户上传 Agent 配置文件（JSON、YAML），动态调整 Agent 行为
- **数据上传**：用户上传数据文件，Agent 进行分析和处理

### 学习重心

| 内容 | 深度 | 理由 |
|------|------|------|
| Form 表单数据 | ⭐ 了解即可 | Agent项目中主要用JSON接口，表单用得少 |
| UploadFile | ⚠️ 适度了解 | 知识库场景会用到，但不算核心高频 |
| 文件校验（大小/类型） | 🔴 必须掌握 | 安全底线，任何文件上传都必须做校验 |

### 哪些内容浅尝，哪些必须深挖

- **浅尝**：表单数据处理的基本语法，知道 Form 和 Body 的区别就行
- **深挖**：文件校验和安全限制——这是生产环境的必做项，不做就等于给黑客留了后门
